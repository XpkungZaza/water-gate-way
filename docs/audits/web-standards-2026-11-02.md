Scope: the front end (`src/app/**/*.tsx`, `src/components`, `src/hooks`, `src/app/globals.css`, `next.config.ts`) of the Water Gate Way dashboard (Next.js 16, React 19, Tailwind v4). Every claim below was checked by reading the code; anything not verifiable by reading is marked as such.

## Recommended, not done (with why)

1. **`script-src`/`style-src` `'unsafe-inline'` (known debt)** — documented in `next.config.ts`. Removing it needs a nonce-based CSP wired through Next's document rendering; out of this change's scope, and naive removal breaks Next's inline bootstrap/RSC payload scripts.
2. **`https://unpkg.com` in `img-src`** — `WaterGateMap.tsx` pulls Leaflet marker PNGs from unpkg at runtime (third-party availability + privacy). The config comment already prescribes the fix: vendor the three PNGs into `/public` and drop the host. `WaterGateMap.tsx` is not in this change's allowed files.
3. **Manifest icons do not exist yet** — `manifest.ts` references `/icon.png` (192×192) and `/apple-icon.png` (180×180) as briefed, but `public/` currently holds only `logo-mark.png` and `logo.png`. The two PNGs must be added (asset owner), otherwise the manifest points at 404s.
4. **Recharts is eager in the dashboard bundle** — `DashboardClient.tsx` statically imports `WaterLevelChart` (recharts, ~100 kB min+gzip), so it loads on every dashboard visit. The Leaflet map **is** lazy: `WaterGateMapLoader.tsx` uses `next/dynamic` with `ssr: false`, so Leaflet ships as a separate on-demand chunk. Recommend `dynamic()` for the chart the same way. (`DashboardClient.tsx` was editable here only for `id="main"`.)
5. **Some interactive targets under 44 px** — `btn`/`input-field`/nav items/tabs/table actions are `min-h-11` (44 px) ✓, but the header sign-out button (`h-9`), the admin panel "จัดการ…" links and the chart's "ดาวน์โหลด CSV" link (`min-h-9`, 36 px) fall short on touch. Raising them to `min-h-11` is a visual change to components owned by other agents.
6. **Chart failure logs every 5 min** — `WaterLevelChart.tsx` calls `console.error` on each failed poll (`POLL_MS = 5 min`), so a long outage writes a line per interval. Consider logging only the first failure or demoting to `console.warn/debug` in production. The camera player already gates its logging to dev-only — good pattern to copy.
7. **Map is pointer-only** — Leaflet's `MapContainer` is not keyboard-operable. Mitigated: the parallel gate list (`<aside id="gate-list">` with real `<Link>`s) reaches every dashboard without the map, so the information is not mouse-gated. A keyboard-pannable map is a Leaflet-level project.
8. **Telemetry status changes are not announced** — the online/stale pills and live values change without an `aria-live` region. For a wall-board primary use this is usually desirable (no chatter), but an operator-specific summary region could be added later.
9. **Only a root error boundary** — any render error anywhere falls to the root `error.tsx` and loses the page frame. Segment-level `dashboard/error.tsx` would keep the app bar alive during a telemetry failure; not in this change's allowed file list.

## Checked and fine

- **Semantic HTML / headings** — one `h1` per page (home: "ประตูน้ำ"; dashboard: gate name in both variants; admin: shell title; login: wordmark image with `alt="Water Gate Way"`; register: "สมัครใช้งาน"). Headings nest correctly (`h2` panels/sections, `h3` reading cards). Landmarks: exactly one `<main>` per page, `<nav>`s labelled (`aria-label="เมนูหลัก"`, `"ส่วนของผู้ดูแลระบบ"`), gate list is an `<aside>`, control rail an `<aside>`, reading groups are `<dl>`s.
- **Forms** — every input has a wrapping `<label>` or `htmlFor`/`id`; `autocomplete="email"`, `"current-password"`, `"new-password"` set where appropriate; constraints (`required`, `minLength`, `maxLength`, `pattern`) with `aria-describedby` rule hints and `aria-invalid` on the register form; per-row controls that repeat visually get distinct `aria-label`s (role select, reset password, admin tabs use `aria-current="page"`); destructive admin actions ask for confirmation. Table has a `sr-only` `h2` and column headers.
- **Keyboard focus** — global `:focus-visible` ring (2 px accent, 2 px offset) on everything; DOM order matches visual order; folding uses native `<details>/<summary>`; busy rows use `aria-disabled` instead of `disabled` so focus is never thrown away; command status line is `aria-live="polite"` with reserved height (no layout jumps); submit buttons expose `aria-busy`.
- **Colour contrast** — `--color-muted #55606a` measured (WCAG relative luminance): **6.43:1 on white surfaces, 5.50:1 on `bg-surface-2`, 5.87:1 on the page background** — passes AA (4.5:1) everywhere muted text is used. State colours never carry meaning alone: every pill pairs colour with a word and a dot (`StatePill`, `DeviceSwitch`, camera status chips).
- **Touch targets** — `btn`, `input-field`, nav items, admin tabs, table row actions and camera retry are ≥ 44 px (see item 5 for the three exceptions).
- **Responsive 390 / 768 / 1440** (by reading the breakpoints) — 390: single-column grids, camera tiles 1-across, admin table scrolls inside its frame, dashboard phone order puts water level first, page never scrolls sideways (`min-w-0` on grid children, `overflow-x-auto` wrappers); 768 (`sm`/`md`): readings 2-up, cameras 3-across, create-user form 2-col; 1440 (`lg`): home splits 360 px list + map, dashboard gets the 384 px sticky rail, admin centers at `max-w-6xl`, dashboard caps at `max-w-[1376px]`.
- **Loading / error / empty states** — every async surface has all three: gate list empty state; chart loading/error+retry/empty at fixed height (no jumps); camera tiles connecting → offline + retry with backoff (never gives up, pauses when the tab hides); command lifecycle sending → waiting → timeout/retry → confirmed; page-level loading skeletons, error boundary, 404 added by this change.
- **`next/image`** — used for the brand mark and wordmark (fixed `width`/`height`, decorative `alt=""` on the mark, naming alt on the wordmark, `priority` on the wordmark). `images.unoptimized` is set in `next.config.ts` with a documented security rationale (`/_next/image` is an unauthenticated endpoint); map tiles are plain Leaflet `<img>`s by design.
- **Frontend security** — no `dangerouslySetInnerHTML` anywhere in `src/` (grepped); no `target="_blank"` (so no rel concerns); no `localStorage`/`sessionStorage` (session rides the httpOnly cookie); third-party hosts limited to `*.tile.openstreetmap.org` and `unpkg.com`, both pinned in `img-src` (item 2); OSM attribution rendered by the TileLayer; all fetches are same-origin authenticated routes with 401 → redirect-to-login handling.
- **Motion** — the map disables tile fade to avoid a blank-map flash; charts set `isAnimationActive={false}` (straight segments, no smoothing lies); `globals.css` kills all animation/transition under `prefers-reduced-motion`.
